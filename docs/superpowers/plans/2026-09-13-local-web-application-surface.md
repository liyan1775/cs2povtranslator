# 本地管理界面基础与查询层实施计划

**阶段标识：** 02E（对应 M1 本地 API/Web 管理界面）  
**计划状态（2026-09-14）：** 02E-4 已完成，交付内容包括固定 Chromium 验收依赖、合成 Web Job 夹具、失败产物目录和 CI 浏览器任务；GitHub 多平台检查已通过。
**前置条件：** 02D-5 已合并至 `master`；当前版本 Job 的仓储、语言数据图、Draft/Reviewed 时间线和字幕导出服务均已通过跨进程验收。  
**实施原则：** 查询层只提供当前版本领域数据的受控投影；所有写入继续通过应用服务和仓储写入权完成；本阶段不改变旧版 CLI 的行为和持久格式。

## 目标

为 M1 建立可供 Web 和 CLI 复用的本地查询入口，先交付只读的工作区、DemoAsset、当前版本 Job、Job 事件和回合数据查看能力。入口必须在工作区边界内运行，返回稳定的 JSON 错误结构，并保留当前 Job 的损坏隔离、运行状态投影和隐私约束。

## 范围约束

- 本阶段只服务当前版本 Job，不扫描或迁移旧版 `manifest.json` 目录。
- Web 层不得直接读取 Job 文件或重建领域校验；所有数据通过 `WorkspaceService`、`FileSystemDemoAssetRepository` 和 `FileSystemJobRepository` 获取。
- API 默认只绑定回环地址，不接收或返回 API Key、外部绝对路径、Demo 内容和系统临时路径。
- 不在 Web 层复制翻译、复核、导出或任务调度逻辑；需要写入的操作留到后续子阶段，并必须复用既有应用服务。
- 首个版本采用 Python 标准库 WSGI 与 `wsgiref.simple_server`，以保持 Python 3.11–3.13 的轻量安装和 Windows 可启动性。该选择记录为当前实现决策；若后续页面复杂度证明需要更完整的框架，再以独立 ADR 评估迁移。

## 阶段划分

### 02E-1：只读查询层与本地 HTTP 基础

- 新增 Web 查询应用服务，将工作区诊断、DemoAsset 列表、Job 列表、Job 详情、事件和单回合语言数据转换为稳定的 JSON 投影。
- 新增纯 WSGI API 和本地开发服务器；统一处理路由、JSON 编码、参数校验、404 和领域/仓储错误。
- 提供最小可访问的 Job 列表页面，显示阶段、运行状态、回合进度、健康状态和刷新后的最新状态。
- 通过 WSGI 测试覆盖健康检查、工作区状态、列表排序、Job 详情、回合投影、无效 ID、未知路由、损坏 Job 隔离和私密字段排除。

### 02E-2：复核查询与媒体预览边界

- 提供按回合查看原始 ASR、理解来源、翻译、置信度、依据和当前复核决定的投影。
- 将音频以当前 Job 的持久媒体引用和工作区相对路径保存；媒体文件仅通过清单 ID 的受控响应提供，不通过通用静态文件路由暴露。
- 先补复核页面对象和可访问选择器，再实现浏览器级验证。

### 02E-3：复核写入与 M1 主流程

- 通过应用服务支持单条复核、整回合/整项确认、Draft/Reviewed 门禁和正式字幕导出。
- 所有写操作使用 Job writer claim、manifest CAS 和领域合成校验；并发冲突返回可操作的稳定错误。
- 增加创建 Job、恢复/取消任务和导出状态查询入口；不新增 Web 专用业务状态。

## 02E-1 验收门禁

1. 查询应用服务可在不启动 HTTP 服务器的情况下独立测试。
2. API 的所有成功响应为 JSON；错误响应包含 `code`、`message_zh` 和 `suggestion_zh`。
3. Job 列表沿用仓储返回顺序，并保留损坏 Job 的健康状态和诊断信息；单个损坏 Job 不影响其他 Job。
4. Job 详情不返回工作区绝对路径、访问令牌、Demo 原始内容或系统临时路径。
5. 回合查询按 Demo 时间和稳定 Cue ID 排序，不依赖文件枚举顺序或任务完成顺序。
6. HTTP 服务器默认仅监听 `127.0.0.1`，启动参数能够显式指定端口，且模块可在 Windows 上编译和启动。
7. 既有测试、金标准回放、当前 Job 跨进程验收和仓库卫生检查保持通过。
