## 3. 并行准备：真实理解翻译评测

在 M0 期间准备可复用的评测协议；不得以人工编写的预期输出冒充模型实测。真实素材保持本地，仅在有明确授权时纳入可公开夹具。

1. 从既有本地验收素材选择代表性回合，覆盖点位谐音、正常无需修正的表达、多人重叠、残缺语句和上下文不足案例。
2. 标注原始转录、必要上下文、可接受解释及不可推断内容；原始转录始终保留。
3. 固定开发集与独立保留集，记录样本版本、标注来源和分歧处理；禁止根据保留集持续调参。
4. 比较旧版直接翻译与新版理解翻译；分别统计意图解释正确率、错误纠正率、正常原文误改率、无依据新增信息、人工修改率、延迟与调用成本。
5. 适配器调参前冻结样本规模及数值验收阈值；阈值基于可核验基线制定，不事后迎合结果。早期小样本仅作可行性证据。
6. 准确性标注存在争议时由人工复核；模型自评不能单独作为最终质量结论。

真实模型调用前必须具备正式秘密存储、固定配置快照、匿名化上下文构造和请求数据预览。准备评测不授权读取散落密钥或自动发送本地媒体。

## 4. M1：最小可用产品流程

依赖 M0 完成和既有管线适配验证。交付可运行链路：

`Demo 导入 → 回合/语音/转录 → 理解翻译 → 人工复核 → 字幕导出 → 同版本重开`

范围：

- 复用已有解析、语音、ASR 和字幕实现，通过新应用服务接入；先建立旧行为比较基线。
- 提供一个可配置的模型服务接入及必要秘密管理、连接诊断与调用快照。
- 提供最小 Web 操作界面：创建任务、观察进度、原文/解释/翻译对照、编辑与确认、草稿/正式导出、重新打开。
- Web 与 CLI 复用同一应用服务；每条界面主流程交付时同步添加浏览器 E2E。
- 必须保留草稿/正式输出的复核门禁和调用数据边界。
- 知识数据库、完整服务商预设目录、知识审批管理及视频能力不作为 M1 前置条件；配置指纹仍明确记录当前固定知识修订。

验收：真实 Demo 产物抽检、理解翻译保留集评测、时间对齐检查、取消/恢复测试、重开后人工修订一致性、用户可操作性验收。合成回放不得替代真实语言质量与时间精度验收。

## 5. M2：完整管理与知识闭环

基于 M1 的实际反馈增加服务商级限流及并发策略校准、多配置管理、已审批知识检索、候选审批/撤销、版本追踪、模型与存储管理。所有修改须保持既有任务配置快照和原始来源可追溯。

## 6. M3：视频输出与硬件集成

完成新版绿幕、RenderBundle 和通用合成，再在具备 CS2/GPU 的机器验证真实 POV 录制。缺少录像能力不阻塞字幕与绿幕交付。

## 7. 外部工具技术验证

语音提取候选试验采用总体计划的三个代表性 Demo，输出覆盖、时间精度、性能、诊断和分发可行性结论。既有提取器满足 M1 验收时，候选试验不阻塞 M1；无法满足必要语音覆盖或时间精度时，问题升级为明确的数据质量阻断项。

每个候选只进入有记录的采用、按场景回退或暂缓状态。追加试验必须指向已复现问题，不以持续探索替代交付。

## 8. 集成与验收协议

- 日常验证针对变更行为与依赖模块；合并前运行全量测试、契约/进程回放、仓库卫生、Ruff 与差异检查。
- 独立审查发现的问题先复现，再修复与回归；仅在有新改动或未解决问题时追加验证。
- 提交只包含明确源码、测试和文档；不改写远程历史。
- 必须查询 PR 实际 HEAD 的全部检查结果后才合并；不能以未配置强制检查时的自动合并命令代替等待。
- 合并后核验主线对应提交的 CI，并记录提交、PR、测试结果和未覆盖项。
- 里程碑状态区分“设计完成”“实现完成”“本地验证通过”“已合并”“真实场景验收通过”；不得用测试数量替代产品交付状态。
